// what it does

  • Routes bottles across the fleet. A bottle arrives at Cocapn addressed to a ship. Cocapn reads the envelope and forwards it. No magic — just routing.
  • Balances the fleet conservation budget. Each ship has its own γ and η. Cocapn tracks the fleet total: Σγ + Ση = C. If one ship runs hot, Cocapn adjusts the fleet distribution.
  • Aggregates ship responses. When multiple ships respond to a coordinated request, Cocapn collects the bottles and produces a single fleet-level response.
  • Monitors fleet health. Each ship's state is visible to Cocapn. It sees who's active, who's drained, who's overloaded. Not because it's special — because it's connected to everyone.

// how it works — data flow

  1. Bottle arrives at Cocapn

     Agent α ──── bottle ────▶ ■ Cocapn

  2. Cocapn reads envelope, routes to destination ship

     ■ Cocapn ──── bottle ────▶ Ship β
                                  dst field determines target

  3. Ship processes, responds

     Ship β ──── bottle ────▶ ■ Cocapn
                                  response bottle, reversed src/dst

  4. Cocapn aggregates (if multi-ship) and forwards reply

     ■ Cocapn ──── bottle ────▶ Agent α
                                  fleet-level response

  5. Conservation enforced at every hop

     each bottle: γ + η = C
     fleet total: Σ(γ) + Σ(η) = C_fleet

// conservation at fleet level

The same law. One level up.

ship level
γship + ηship = Cship
Every ship conserves energy individually. Injection plus dissipation equals a constant.
fleet level
Σ γship + Σ ηship = Cfleet
equivalently:   γ1 + γ2 + … + γn + η1 + η2 + … + ηn = Cfleet
Sum every ship's gamma. Sum every ship's eta. Their total is the fleet constant.
This is the same conservation law — just summed over the fleet. Cocapn enforces it.
what this means
If ship α runs a surplus (high γ), some other ship must be absorbing that energy (high η). The fleet total stays constant. Cocapn sees the full picture and can rebalance — routing bottles from hot ships to cold ones, ensuring no single ship starves or drowns.

// the code — Cocapn is a ship

Same trait. Same interface. Cocapn implements Agent just like every other ship.

crates/cocapn/src/lib.rs
use superinstance::{Agent, Bottle, AgentState, Ternary};

/// The Agent trait — every ship implements this.
/// Cocapn is no exception.
pub trait Agent {
    fn receive(&mut self, bottle: Bottle) -> Bottle;
    fn inspect(&self) -> AgentState;
}

/// Cocapn — Captain of the Fleet.
/// First among equals. A ship with wider vision.
pub struct Cocapn {
    fleet: FleetRegistry,
    budget: FleetBudget,
}

impl Agent for Cocapn {
    fn receive(&mut self, bottle: Bottle) -> Bottle {
        let dst = bottle.dst();

        if dst == "cocapn" {
            // Addressed to Cocapn itself — handle directly.
            self.handle_fleet_query(bottle)
        } else {
            // Route to the destination ship.
            let ship = self.fleet.get(dst);
            let response = ship.receive(bottle);

            // Track fleet-level conservation.
            self.budget.record(&response);
            self.budget.enforce();  // Σγ + Ση = C_fleet

            response
        }
    }

    fn inspect(&self) -> AgentState {
        AgentState::Active
    }
}

impl Cocapn {
    fn handle_fleet_query(&self, bottle: Bottle) -> Bottle {
        let fleet_gamma: f64 = self.fleet.iter()
            .map(|s| s.gamma()).sum();
        let fleet_eta: f64 = self.fleet.iter()
            .map(|s| s.eta()).sum();

        Bottle::new("cocapn", bottle.src())
            .gamma(fleet_gamma)
            .eta(fleet_eta)
            .body(format!(
                "fleet: {} ships, C={}",
                self.fleet.len(),
                fleet_gamma + fleet_eta,
            ))
            .seal()
    }
}

// the key insight

Cocapn IS a ship.

It receives bottles. It responds to bottles. It implements the same Agent trait as every other ship in the fleet.

The only difference is scope. A regular ship sees its own γ and η. Cocapn sees everyone's. It aggregates Σγ and Ση across the entire fleet and enforces conservation at the fleet level.

This isn't a hierarchy. It's first among equals. Every ship is a peer. Cocapn just has the widest view — because it's connected to every ship, not because it's above them.

The fleet is peer-to-peer. Cocapn is the node with the most edges.

peer-to-peer fleet topology Ship α ╱ │ ╲ ╱ │ ╲ Ship δ───■ Cocapn───Ship β ╲ │ ╱ ╲ │ ╱ Ship γ Cocapn has the most connections. It's a ship with more edges. Not a king with subjects.
