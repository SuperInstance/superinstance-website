📐 Tensor Cells

Cells aren't just scalars. They have weight, gravity, and distance in tensor space. Connections propagate like physics. Memory pools and caches are cells too.

The cell isn't a value. It's a position in a tensor.

A Quilt sheet is a graph, but it's more useful to think of it as a tensor field. Every cell has a position. Every connection is a vector. The whole sheet is a navigable N-dimensional space where:

  • Cells have weight — a scalar influence on their neighbors. A high-weight cell propagates strongly; a low-weight cell is a leaf.
  • Cells have gravity — an attraction to other cells. A high-gravity cell pulls neighboring values toward itself.
  • Cells have distance — their position in tensor space. Two cells at distance d interact with strength 1/(1+d²).
  • Connections have direction and magnitude — they aren't just edges, they're vectors with phase and amplitude.
  • Propagations are physical — they follow the geometry of the tensor, not just the topology of the graph.
Why this matters: A spreadsheet re-evaluates dependencies topologically. A Quilt sheet re-evaluates physically. The difference is that downstream cells don't just receive values — they receive values with momentum. A change in cell A doesn't just update cell B; it pushes B with a force proportional to A's weight and inversely proportional to the squared distance. This is the difference between a lookup table and a simulation.

Cell attributes

cells:
  sensor.boat.heading:
    kind: value
    value: 45
    
    # New: tensor-space attributes
    weight: 1.0          # How strongly this cell propagates
    gravity: 0.0         # Does this cell pull neighbors toward itself?
    position: [1, 2, 0]  # x, y, z in tensor space
    distance: 1.414      # Auto-computed distance from origin
    
  # A cell with high gravity — values nearby tend toward it
  target.heading:
    kind: value
    value: 90
    gravity: 0.8         # Strong attractor
    position: [0, 0, 0]
    
  # A cell with low weight — terminal, doesn't propagate far
  display.label:
    kind: formula
    formula: "round(sensor.boat.heading) + '°'"
    weight: 0.1          # Local effect only

Distance and propagation

The propagation rule is geometric, not just topological. When a cell's value changes, the change propagates to dependents with strength:

delta_received = delta * (1 / (1 + distance²)) * weight * (1 - damping)

This means:

  • Far-away cells are damped. A change in cell A might be 99% absorbed before it reaches a cell 100 units away.
  • Heavy cells propagate strongly. A weight-10 cell can affect the whole sheet; a weight-0.1 cell can barely affect its immediate neighbors.
  • Damping prevents oscillation. A high-damping sheet is stable; a low-damping sheet can resonate.

Why "tensor encoding" matters

Most data systems treat records as rows in a table. That's a 1D representation — every record is a point on a line, ordered by key.

Quilt treats records as tensors:

  • Each cell is a point in N-dimensional space. position: [x, y, z, ...] places it in the tensor field.
  • Cells with similar positions are neighbors. They're physically close, so they interact strongly.
  • Cells with similar attributes are clustered. Two cells in the same tier (esp32, jetson) are close in tier-space; two cells in the same sheet are close in sheet-space.
  • Projections are visualizations. The 2D heatmap is a projection from N dimensions to 2. The 3D synoptic is a projection from N to 3. The TUI view is a projection from N to 1.
  • The same data renders differently in different projections. A finance heatmap shows load. A 3D graph shows topology. A Markdown table shows a snapshot. They're all views of the same tensor.

Optimization through physical setup

Because the system is geometric, you can optimize it by setting up its geometry:

  • Place hot cells near each other. Cells that update together should be physically close; their propagation is fast.
  • Place stable cells far from unstable ones. A cell that updates 1000x/sec shouldn't be near a cell that updates 1x/min — the stable cell wastes time damping fast updates.
  • Use gravity for invariants. If a value should always converge to a target, give the target high gravity. The system self-corrects.
  • Use distance for batching. Cells at distance > 10 from the change can be updated in a batch, asynchronously.
  • Use weight for prioritization. When resources are tight, update the highest-weight cells first.

The math (when you need it)

The propagation tensor at any moment is a rank-N tensor P where P[i, j, k, ...] is the influence of cell i on cell j at step k in subsystem .... The state update is:

state[t+1] = state[t] + dt * (propagation(state, P) - damping * state[t])

For most practical sheets this is overkill. The discrete propagation we use in production is simpler:

for each changed cell c:
  for each dependent d, ordered by distance:
    d.value += (c.value - d.value) * weight * (1 / (1 + distance²)) * damping
    if abs(d.value - d.last_value) > threshold:
      propagate(d)

Same behavior, easier to debug, runs in O(edges × max_depth).
